# Akato 工作空間第一階段

第一階段把目前散落在 CEO 手機裡的接單資訊，轉成可由多人接手的工作資料，但不自動傳訊息給客戶，也不讓 AI 直接確認訂單。

## 主流程

1. 保留客戶在 LINE 的原始文字、截圖或檔案。
2. CEO 逐題確認收禮人、品項、價位、作品要求、賀卡與配送資料。
3. 一筆訂單拆成一盆一張的作品卡。
4. 產生給珊珊的賀卡任務，以及給製作者的作品需求卡。
5. 後續階段才加入作品照、插卡照、現場照與客戶成果包。

## 資料原則

- 原始 LINE 內容採追加方式保存，後來的修改不能覆蓋先前訊息。
- 一盆作品是一筆 `admin_work_order_items`，不能只用總數代表多個收禮人。
- 照片預設不提供客戶；只有人工勾選的照片才能進成果包。
- 第一階段資料表沒有公開或登入者直連政策，只允許後續受保護的伺服器流程存取。
- 現有 `/admin/orders?key=...` 只能繼續使用匿名 mock，不得放真實客戶資料。

2. 建立伺服器端訂單新增與查詢 API。
3. 套用 migration，建立私密照片 bucket。
4. 以匿名的師大多棟、多樓層情境驗證一盆一張的配送標籤。
